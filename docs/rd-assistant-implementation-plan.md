# 药企研发总监助手：实施计划与复刻验收

状态：核心合成验收通过，分享仓库代码已推送并读回。对应 revision 与范围见 `docs/rd-publish-validation.json`，本计划不把本地测试替代 WorkBuddy 本体验收。日期：2026-10-09。

## 用户要求与交付范围

WorkBuddy 作为中台和真实运行宿主；外部通讯直接复用已有连接器，不施工通用 bridge。包含角色 `agent.md`、Superpowers 工作方法、精选生物医药与通用科学技能、PPT-master、现有 Obsidian 系统。智慧芽 MCP 与邮件连接仅写设计与现场实施说明，其余全部在 WorkBuddy 中实际完成可追溯任务。跑通后再同步分享仓库，使另一台机器可按同一说明复刻。

邮件来源实施方案见 `docs/email/workbuddy_email_assistant_implementation_plan.md`；当前阶段不读取真实邮箱、不建立常驻邮件监控、不发送提醒。现有方案中的专项通知适配器属于现场邮件实施候选，不能据此另建通用通讯系统。

## 分工与路径

主 agent 为规划者、唯一集成人和最终验收人，负责根规则、角色、初始化与复制脚本、介绍 HTML、实施计划、真实 WorkBuddy 任务与共享验收记录。

| 工作 | 唯一 worker 路径 | 最终审核 |
|---|---|---|
| WorkBuddy 官方能力与本机运行入口调查 | research/workbuddy-runtime.md | 主 agent 验证真正的宿主与任务路径 |
| 科学技能筛选、固定版本与可执行样例 | integrations/scientific/、vendor/scientific-agent-skills/ | 来源、许可、脚本数值与适用边界 |
| 工作流与 PPT-master 集成 | integrations/workflow/、integrations/presentation/、vendor/superpowers/、vendor/ppt-master/ | 工作方法、实际 PPT、渲染与固定引用 |
| 总集成、HTML 与复刻 | 其他明确属于本任务的路径 | 唯一集成人串行验收与定向提交 |

所有工作在独立 `feat/pharma-assistant-20261009` 工作树完成；个人知识库保持只读。worker 无 Git/发布权限。

## 验收用例

| 编号 | 真实宿主任务 | 必要证据 |
|---|---|---|
| WB-01 | 在新工作区发现角色与 skills | WorkBuddy 主体/版本、项目路径、真实任务文本与回复，读取入口记录 |
| WB-02 | 合成管线问题经澄清→计划→执行→验证 | 问题/范围、批准后计划、来源表、执行产物、核验结论；不调用未配置智慧芽 |
| WB-03 | 临床前合成数据分析 | 数据 hash、实际工具/脚本执行、结果文件、统计限制、数值复查 |
| WB-04 | PPT 呈现上述结果 | 真实 WorkBuddy 任务、实际 PPT 与渲染、页数和数值检查 |
| WB-05 | 收藏来源到 Obsidian | 真任务、raw与note、完整逐篇元数据、manifest、校验结果 |
| WB-06 | 新任务从库中查回信息 | 真任务、引用本次源笔记、内容与原料一致；不使用预置答案代替检索 |
| REPL-01 | 新空路径重复 bootstrap | 所需文件/技能数量、锁文件与hash、重复执行不覆盖用户文件 |
| DOC-01 | HTML 与实施说明 | 带日期和来源，四种宽度与离线验证、介绍范围准确 |
| EXT-01 | 智慧芽与邮件现场连接设计 | 正式来源和来源文件、默认不连接/不监控，现场checklist |

真实 WorkBuddy task 的 handles 与账号相关日志保存在不入 Git 的 `.local/`；公开验收摘要只记录脱敏的运行方法、时间、任务类别与产物 hash。进程存在、CLI 兼容或本地 mock 通过不足以证明本体验收。

## 继续执行与故障恢复

初始化、原料与产物均不覆盖用户已有内容。停止/重试前检查实际运行任务状态，复用尚在运行的 handle；不因观察超时就重新开任务。缺少账号权限、模型额度或工具审批时记录具体 blocker，同时继续完成不依赖该条件的工作。所有阶段保持可续跑，不提前把全部目标标为完成。
