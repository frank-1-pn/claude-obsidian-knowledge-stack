01 / 三层文件架构

先存下来，再写清楚，最后连起来。

三层分别解决“原文在哪里”“这篇讲什么”“它与其他知识有什么关系”。它们是资料在知识库中的三个职责层。

LAYER 01 · SOURCE

原始文件层

保存实际取得的网页正文、PDF / Office 原件、截图、README、字幕或会话记录。原料先归档，整理时才能回查；重试和更新追加新快照。

.raw/<type>/
YYYY-MM-DD_<slug>.<ext>
回答：依据是什么？

LAYER 02 · NOTE

可检索笔记层

每份来源整理成一篇原子笔记。写清标题、标签、100–200 字检索摘要，保留阅读主体，并用原料路径和溯源信息说明出处与实际核实方式。

wiki/sources/<主题>/<标题>.md
tags · abstract · raw_path · provenance
回答：它讲什么？怎样找到？

LAYER 03 · NETWORK

分类与关联层

笔记进入合适的主题文件夹，再通过目录索引、相关笔记双链与集中关系图建立联系。按主题浏览、按时间回顾、跨来源比较都有明确入口。

主题文件夹 · index.md · _index.md
related · meta/notes-graph.md
回答：放哪里？能与谁一起看？

第三层组织的是第二层的同一份笔记。“笔记按主题归位 + 索引提供入口 + 双链表示相关 + 关系图说明联系”，共同构成知识网络。

组织方式各自解决的问题怎么用
主题文件夹稳定的大类归属根据主要讨论对象，把笔记放进对应领域。
标签 tags横跨文件夹的检索维度用准确的小写、连字符标签，例如 agent-memory。
索引与最新笔记浏览和回顾入口主题从 index / _index 进入，时间从“最新笔记”进入。
双链与关系图跨笔记的意义联系related 链接相关笔记，关系图说明比较、补充或分歧。

02 / 一份资料怎样进入三层

用一个小例子，看见文件的变化。

点击切换下面的三层。示例材料与笔记均为本页演示编写，用来展示结构；没有调用真实连接器，也没有展示私人文章。

示例主题：一套可追溯的 AI 笔记流程结构演示 / 非真实入库

先保留实际材料

记录来源身份与获取时间，保存完整取得的内容。连接器只返回 Markdown，就如实归档 Markdown；只有确实取得 HTML 时才保存 HTML。

.raw/webfetch/2026-10-08_traceable-notes.md

来源：本页合成材料　·　日期：2026-10-08　·　格式：Markdown

可追溯笔记的基本流程

写笔记前先保存原始材料。每一份来源对应一篇整理笔记，在笔记里记录原料的位置，方便日后回查。

笔记的标题、标签和摘要帮助检索；笔记进入对应主题文件夹，通过索引与相关笔记建立联系。只有相关入口、日志和检查完成后，才登记为入库完成。

归档后不覆盖原料。若后来取得更完整的版本，保留旧文件，再追加新快照。

整理成能读、能查的笔记

同一来源的内容保持完整上下文。摘要承担快速检索，正文承担阅读理解，原料路径承担回溯。

wiki/sources/工作流与工具/AI 笔记流程的归档与检索设计.md

AI 笔记流程的归档与检索设计

knowledge-basenote-as-atomsource-traceability
检索摘要

这份示例材料介绍 AI 辅助笔记的可追溯流程：先保存原始文件，再为每份来源建立一篇带标签与检索摘要的笔记，最后通过主题文件夹、索引和双链建立联系。核心机制是原料路径保留出处、单篇笔记保留上下文、集中关系图组织跨来源关系。适合回答“怎样减少重复笔记”“如何找回原文”“整理完成后还要更新哪些入口”等问题，也可用于检查一次入库是否已经闭环。

AI 补充 / 类比，非原文：可以把原料理解为书的原件，把笔记理解为带索引词的阅读记录，把第三层理解为书架目录与相互参照的阅读路线。

raw_path 指向第一层原料；provenance 记录真实模型、日期及已执行的核实手段。这里展示结构，不填写虚构核实结果。

归位，并建立有依据的联系

文件夹解决“放在哪”，索引解决“从哪进入”，双链与关系图解决“为什么值得一起看”。下面几个节点都是演示节点。

03 / 十个 skills

把十种能力，变成稳定的操作方法。

Skill 是按任务读取的操作说明，告诉 AI 遵循哪些约束、读取什么、输出到哪里。它不等于必须另外安装十个 Obsidian 插件；实际工具能力由 WorkBuddy 或其他宿主提供。

显示 10 / 10 个 skills

wiki

编排与维护

系统入口与任务编排

检查知识库结构，初始化缺失项，读取近期上下文，再把具体请求交给对应 skill。建立新库前检查 Obsidian，缺少时执行官方安装流程。

你可以说：“读一下规则，帮我搭好这套知识库。”

结果：明确的目录、入口、规则和任务路由。

wiki-ingest

输入与沉淀

把来源整理入库

读取完整材料，先存原料，再写一篇带标签、摘要和溯源信息的原子笔记；完成分类、关系、入口与逐篇验收。

你可以说：“把这份文章按入库规则整理进去。”

结果：原料快照 + 单篇笔记 + 验收后的索引与记录。

wiki-query

检索与呈现

基于已有笔记回答问题

先读近期状态和索引，再定位相关笔记，结合来源给出有引用的回答。默认只读，库里没依据时说明缺口。

你可以说：“我之前收集的几种 AI 记忆方案有什么差异？”

结果：引用具体笔记的回答；保存需明确提出。

wiki-lint

编排与维护

检查知识库是否健康

检查死链、孤立笔记、字段缺失、空章节、过期入口与关系缺口。先给报告，源笔记的修改遵守内容保护规则。

你可以说：“检查笔记库，看看有没有死链和漏掉的索引。”

结果：问题清单、涉及路径和修复建议。

save

输入与沉淀

保存一次讨论或洞见

把值得保留的对话先归档，再整理为一个 sessions 文件，写清决定、分析和相关上下文，并与已有笔记建立联系。

你可以说：“保存这次讨论，尤其是决定和理由。”

结果：会话原料 + 一篇会话笔记。

autoresearch

输入与沉淀

有边界的迭代研究

明确发起后，搜索、读取并归档来源，补足关键缺口，默认形成一篇综述，标明来源、分歧与尚未解决的问题。

你可以说：“研究这个主题，默认只建一篇综述。”

结果：多份来源快照 + 一篇综合研究笔记。

canvas

检索与呈现

把现有知识放到画布上

把已有笔记、图片、文本卡和 PDF 展示在 Canvas 中，通过分组与空间布局表达阅读路线。保持内容层与关系元数据的一致性。

你可以说：“把这些笔记放到同一张画布上，展示它们的关系。”

结果：可在 Obsidian 打开的 .canvas 文件。

defuddle

输入与沉淀

清理网页正文

在适合的网页上去掉导航、广告和模板噪声，得到更易阅读的正文；完整性检查与原料先归档的要求仍然保留。

你可以说：“清理这个网页，再按规则整理入库。”

结果：可读网页快照，供后续整理使用。

obsidian-markdown

检索与呈现

把笔记写成正确的语法

指导 frontmatter、双链、图片嵌入、callout、标题、列表和公式等格式，让笔记在 Obsidian 中正确显示与链接。

你可以说：“按 Obsidian 语法排版，检查 YAML 和双链。”

结果：结构合法、可阅读、可链接的 Markdown。

obsidian-bases

检索与呈现

按属性动态浏览笔记

用 .base 文件按标签、日期、状态等属性筛选笔记，生成表格或卡片视图。视图读取已有笔记属性，适合目录之外的浏览方式。

你可以说：“做一个按主题和状态筛选的笔记视图。”

结果：定义筛选和展示方式的 .base 文件。

没有匹配结果。试试“来源”“保存”或“索引”，或切换到“全部”。

使用时说自然语言即可。AI 按需要读取 skills/<name>/SKILL.md；工具名、斜杠命令和是否支持子 agent，以实际宿主环境为准。

04 / 写入如何闭环

写出草稿，只是流程中的一步。

一篇笔记的完成包含材料、内容、组织和验收。下面按真实执行顺序展示：一篇完整关闭后，再处理下一篇的集成。

01 / 获取

读取与完整性检查

明确来源，检查正文、图片和重要段落是否取得；截断或失败说明实际缺口。

02 / 归档

先保存原始文件

选择 .raw 类型目录，保存不可覆盖的快照，并查重，避免重复整理。

03 / 整理

生成一篇原子笔记

标题、标签、检索摘要、正文、raw_path 与真实 provenance 一起完成。

04 / 组织

分类与 graph / index

笔记归入对应主题文件夹，更新关系图、主索引和相应分类入口。

05 / 留痕

立即记录日志

记录触发、来源取得方式、原料、输出、补充、联系与实际验证结果。

06 / 刷新

更新 hot 与 latest

hot 记录近期状态；最新笔记由脚本按日期生成，不手改生成区块。

07 / 验收

检查文件与内容

解析 YAML，验证原料路径、双链、图片、摘要和入口记录，按范围运行检查。

08 / 完成

最后登记 manifest

验证完成后，写入来源状态与输出路径，作为该来源的持久完成标记。

完成条件：原料可回溯，笔记可阅读和检索，分类与联系有入口，日志与最新笔记已更新，实际检查通过，manifest 最后落盘。

支持子 agent 时：来源独立，集成统一

默认两个独立来源 worker 负责各自的原料、笔记和附件。主线程作为唯一集成人，逐篇核对，再串行维护共享索引、关系、日志与 manifest。Git vault 使用跨会话集成锁。

不支持子 agent 时：串行执行同一流程

如实说明串行处理，保留同样的归档和验收要求。非 Git vault 使用单会话串行方式，避免把不同会话对共享文件的写入混在一起。

05 / 笔记写入规则

让知识积累保持可信、可读、可维护。

点击展开规则和例子。它们来自当前项目规则；执行时根 AGENTS.md 是唯一维护入口，skills 提供具体任务步骤。

01 · 原始资料先归档，而且不覆盖
外部材料先存入 .raw/，再写整理笔记。快照名用 YYYY-MM-DD_<slug>；slug 为最多 10 个小写英文连字符词。失败版本保留，重试追加新快照。
  • 网页：webfetch；公众号：wechat。
  • PDF / Office：pdf；截图：screenshots。
  • GitHub：github；RSS：rss。
  • 字幕、音频转录、会话：transcripts；社交帖：social。
02 · 一份来源对应一篇原子笔记
把来源中的人物、产品、概念、例子和问题保留在同一篇笔记的章节里。跨来源关系集中写进 notes-graph.md。保存会话默认一个 sessions 文件；研究默认一篇综述，只有明确要求研究子页时才扩大结构。
03 · 保护既有笔记的内容与路径
未经“整理这份”明确指令，不改既有源笔记正文、标点、文件名或位置。可维护 frontmatter 的 tags / related。批量改名先提供清单，再检查重名、非法字符、路径长度和反向链接。
04 · 标题说明主题，摘要帮助未来检索
普通标题采用“项目名 + 它是什么 + 可选实现方式”，约 15–38 字。H1 后放 100–200 字 [!abstract]，包含具体对象、准确别名、问题、机制、场景和可回答的问题。合集按系列、数量、日期和代表项目命名，按内容代表性选项目。
05 · 标签准确，减少同义词碎片
标签用准确名称，默认小写、连字符和单数，例如 open-source、agent-memory。遵循受控词表；语义不同的产品名和泛概念保留区别。作者字段统一为 authors。不要为增加命中堆无关关键词。
06 · 保留阅读主体，AI 讲解就地标注
公众号学习笔记采用“检索摘要 → 来源信息 → 阅读主体 → 就地穿插讲解”。解释先说是什么、为什么需要、如何起作用，难点旁放白话、例子或理解卡片，不强凑数量。
  • 原作者观点保留来源口径。
  • AI 解释标“AI 补充 / 非原文”。
  • 类比和推断明确说明。
07 · 原文权限与外部补充清楚区分
可完整使用的原文保留顺序、措辞、论证和重要图片，只转换呈现方式。只有链接且全文转载权限不明时，提供原文链接、学习摘要和适量短引文。其他来源默认只写来源事实；获准加入的来源外事实用 [!external] 标注并附依据，不把模型记忆伪装成原文。
08 · raw_path 与 provenance 写实际证据
raw_path 指向真实归档文件。provenance 包含 schema、真实模型、是否事后回溯、记录日期和实际核实手段。未知模型如实记为 unrecorded；只有完成归档才写 raw-archived。没有记录某种核实方式，只说明“没记录”，不能据此断言“没做”。
09 · 图片按需、附件本地化、手机端可读
只把笔记真正引用的来源图片放到根 _attachments/<note-slug>/，用 Obsidian embed 引用。AI 图注明“示意 / 非原图”，检查文字、结构与事实。标题与标签默认简体中文。列表逐项换行，callout 段落之间保留空的 > 行。显式要求的图片缺失时保持 partial，直到补齐或接受替代。
10 · 逐篇闭环，规则与授权都有边界
每完成一篇，立即更新 graph / index、log、hot / latest、校验，最后写 manifest。只有唯一集成人写共享元数据。YAML、链接和文件路径必须实际检查；初始化检查 Obsidian，缺少时按官方流程自动安装。明确“同步”后才定向 commit / push，连接器的读取能力也不自动授权外发消息。

# 项目名 + 它是什么

> [!abstract] 检索摘要
>

## 来源信息
作者、原始标题、URL、日期、取得方式与覆盖范围。

## 阅读主体
按来源和权限保留原文，或整理学习摘要。

>

related 只链接真实存在的笔记；raw_path 只指向实际归档的文件；verified 只填本次已经执行的核实。模板不代表完成了这些动作。

06 / 怎样把知识找回来

从轻量入口，逐步回到来源。

摘要、标签、文件夹与双链配合使用。AI 先定位线索，再读相关笔记；需要核对原作者意思时，沿 raw_path 回到第一层。

01 / 近期

hot.md

看看最近新增、当前主题和未决事项。

02 / 定位

index / _index

由总索引或主题目录找到相关笔记。

03 / 串联

notes-graph

查看哪些来源可以比较、互补或存在分歧。

04 / 回查

笔记 → 原料

读取正文并引用；有疑问就回到原始快照。

查已有知识“从我的库里查 X，引用对应笔记，说明依据和缺口。”
跨笔记比较“把已有的 A、B 方案放在一起比较，保持各自来源口径。”
