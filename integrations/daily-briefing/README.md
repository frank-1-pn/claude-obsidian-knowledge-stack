# 每日资讯：按你的关注点汇总，摘要与原文一起看

先了解用户每天关注什么，再由 WorkBuddy 按约定时间搜集、去重、总结并推送。用户可以快速读 AI 总结，也可以点击每条的**源新闻链接**查看完整内容。关注范围、篇数、时间、来源和推送渠道都可以定制。

本目录提供配置与任务模板，沿用现有 10 个 Obsidian 技能，不新增技能。当前状态是**模板准备完成**；尚未配置朋友的偏好、运行时接收者或定时任务，也未验收真实推送。

## 先做一次你愿意每天收到的样刊

1. WorkBuddy 读取 [preferences.example.json](preferences.example.json)，根据已知信息填配置，只询问真实缺口。例如：每天关注哪些主题、公司或靶点？几点收到、发到哪里？优先哪些来源、哪些内容不需要？
2. 将配置复制到独立助手工作区的私有运行目录，实际账户、接收者和凭证只在运行时配置，不写分享仓库。示例中的研发主题只是可选起点，不代表用户已经选定。
3. 用 [task-prompt.md](task-prompt.md) 执行一次预演，保存 HTML 日报和简短推送预览，再实际读回文件、检查源链接和摘要。此步不创建调度、不发送。
4. 用户看过样刊、明确启用自动推送后，再由 WorkBuddy 在现场检查当前版本能否建立真实定时任务。如果没有相应能力，使用用户授权的系统任务或运行时调度；说明本机休眠、离线和登录状态对执行的实际影响，不能把一段提示词当作已运行的调度。
5. 验收一次真实触发、生成、发送和接收端读回，记录时间、产物和回执。只有这条链实际成功，才称“已开启每日推送”。用户以后可以修改关注点、发送时间、渠道或暂停。

微信、飞书等读取和发送复用 WorkBuddy 已有连接器；这里不安装新的抓取器或 bridge。渠道连接不可用时如实报告，不切换接收人或改用未经授权的渠道。

## 样刊包含什么

- **今日速览**：几句话说明值得留意的变化，AI 判断与来源事实分开。
- **按关注主题分类的新闻卡片**：标题、来源及发布时间、事实摘要、AI 解读、与你的关注点的关系，以及“查看源新闻”链接。
- **更新标记**：首次报道和已有事件的实质变化分开；同一新闻的多家转载不重复占篇数。
- **覆盖说明**：统计时间窗、可访问来源、失败来源和正文缺失。没有新增符合条件的信息就明确写“今日暂无新增符合关注条件的资讯”，不强凑新闻。

历史展示数据见 [sample.json](sample.json)，摘取自用户 `2026-10-07` 的每日资讯页，保留原有摘要和链接，**未在本次重新核验**。它用于展示阅读方式，不能进入当前日报或冒充当前新闻；其中以“分析：”开头的段落属于原页面 AI 解读。

日报可使用 [briefing-template.md](briefing-template.md) 的内容结构，输出一份能本地打开的 HTML，并准备适合所选渠道的简短消息。消息中的“查看日报”只能使用用户可访问的已授权地址或已验证文件附件，不能填本机路径充当远程链接。

## 内容与投递约定

优先原始发布者、官方公告、监管文件、原始论文和可核查报道；配置多个来源类型，避免把单一媒体的观点当作公认事实。每条保留实际读过的原始 URL，标出来源发布时间、事件时间（确实可知时）和获取时间；使用用户配置的时区与时间窗。转载日期不能代替事件发生时间。

只有标题、摘要或公告片段可读时，注明阅读范围，不补写未读正文。事实数字以来源为准，推断明确标“AI 解读”；医药资讯不能把早期、动物或预测结果写成已经证实的临床效果。链接或正文获取失败须披露；受限内容不绕过限制。摘要控制在合理长度，不默认复制完整新闻。

运行时维护跨日报的事件去重记录和每次投递状态：同一计划、覆盖时间窗、渠道及接收目标派生稳定 `delivery_key`，重试复用同一个 key。发送结果未知时先查已有回执和接收端，不能换 key 重发；只有确认未送达且符合授权重试条件才再次发送。无法查明时保留 `unknown` 并报告。补发、重大提醒和普通日报分别受用户配置控制。

每天的日报保存在运行输出目录，不自动把全部新闻写入 Obsidian。用户点名收藏时，交给现有 `wiki-ingest`：按一份来源一篇原子笔记、原料先归档、摘要与标签、关联与索引、manifest 最后写入的规则处理；后续用 `wiki-query` 找回。

## 配置字段说明

`preferences.example.json` 是待填配置示例，不是已经生效的任务，也不是调度程序。空字符串、`null` 和空数组表示未知或未选择。

| 字段 | 含义 |
| --- | --- |
| `interests` | 主题关键词、公司、靶点、领域及排除项；关键词别名按实际需要填写 |
| `sources` | 优先来源、排除来源、是否只允许指定来源及输出/阅读语言 |
| `coverage` | 回看时长、允许的最大条数、首次启用的回溯范围、无新增时的处理 |
| `schedule` | 用户确认的时区、发送时间、频次及延迟补发策略；默认未启用 |
| `delivery` | 用户选择的渠道、展示方式；真实接收目标另存私有运行配置 |
| `major_alerts` | 是否允许日程外重大提醒、具体触发条件、免打扰时间；默认关闭 |
| `approval` | 样刊是否已确认、用户是否明确启用；两项默认均为 false |

启用前验证时区有效、时间格式为 `HH:mm`、条数与时窗合理、至少有一个关注范围、渠道与接收目标可用、提醒条件无歧义；不把缺省偏好或示例值默认为用户选择。
