# 研发调研工作流

先阅读本文件，再按当前阶段阅读 `../../vendor/superpowers/skills/` 中的对应原文。本集成保留上游原文，仅提供 WorkBuddy 与科研场景的适配；没有安装上游平台钩子，也不宣称具备上游全部原生插件行为。

## 适用边界

Superpowers 是软件开发方法论。科研采用它的澄清、拆解、检查和证据优先原则；代码开发才按适用场景使用 TDD、代码审查和 Git worktree。不得给科学结论套用“测试通过所以事实成立”，不得照搬原文中的自动 commit、清理文件或额外审批流程。仓库 `AGENTS.md`、用户现有授权和任务边界优先。

## 1. Brainstorming：明确真正的问题

参考 `../../vendor/superpowers/skills/brainstorming/SKILL.md`。

- 写回用户已经明确的目的和约束。若必要信息缺失，每次问一个最影响结果的问题。
- 管线调研明确适应症、靶点/机制、模态、地区、阶段、截止日期、竞争维度与最终决策用途。
- 科学问题明确模型、终点、对照、现有证据、可用数据以及输出用途。
- 比较可行的调研策略，说明覆盖率、时效性、成本与证据缺口。用户已经给足范围时直接形成 brief，允许纠正，避免重复授权。
- 使用 `templates/research-brief.md`。真实业务范围选择仍交给用户，技术实现细节由 AI 完成。

## 2. Plan：把问题变成可验收任务

参考 `../../vendor/superpowers/skills/writing-plans/SKILL.md`，使用 `templates/research-plan.md`。

每个任务写清输入、方法、输出路径、依赖、责任人和验收证据。列出检索式、纳入排除标准、来源优先级、去重方法、需要复核的字段及失效条件。智慧芽属于待现场配置的专有数据源；没有真实接入时写明缺口，用可获得来源继续，禁止声称已连接。

**执行门：计划必须先写入实际文件并读回，再运行处理脚本、查询或生成研究结果。** 计划中的待执行任务先记为 pending；执行账本随后追加真实记录，不把事后补写的计划伪装成先计划。已授权且范围明确时无需再索要权限；真正缺少业务范围时保持澄清阶段。审查发现顺序错误时，保留原轮作为预演，再按已审核计划重新实际执行和验证。

## 3. Execute：分步推进并留下记录

参考 `../../vendor/superpowers/skills/executing-plans/SKILL.md` 的任务账本思想，科研不执行其代码提交/TDD命令。

独立资料可由不同 worker 获取；主线程负责共享状态、版本和审核。各任务完成即记录实际命令/检索、时间、输出和限制。失败保留可恢复文件并标 partial；禁止把空结果说成“没有这条管线”。笔记入库遵守现有 raw-first、单篇原子笔记、锁、唯一集成人和 manifest-last 规则。

## 4. Verify：逐项验收后才发布结论

参考 `../../vendor/superpowers/skills/verification-before-completion/SKILL.md`，填写 `templates/evidence-review.md`。

- 科学事实逐条有来源、来源日期、获取日期和原文支持位置，区分事实/推断/假设。
- 核对实体同名、靶点别名、终点、单位、时间点、阶段及地区；冲突并列呈现。
- 管线当前状态与历史最高阶段分别核对；阶段取明确排序的历史最高或来源明确声明的最高字段，不因遍历顺序把较早的低阶段覆盖较新的高阶段。改变截点得到不同的合理结果属于参数敏感性，不因不符合另一截点的固定答案就称它为错误。
- 统计与图表可从输入数据复算，不把演示/合成数据转成真实研发证据。
- PPT 逐页核对来源、数字、单位和图表，检查渲染与可编辑结构。
- 知识库同时检查 raw、摘要、tags、related、索引、graph、日志及 manifest；草稿不算入库完成。
- “本地脚本运行”“WorkBuddy 工具执行”“真实来源访问”“业务验收”分别报告，不互相替代。

## WorkBuddy 操作入口

朋友复制仓库后，先让 WorkBuddy 阅读根目录启动文件和本文件。可直接发：

> 请按 pharma-research-workflow 为我做一次演示管线调研。用公开资料或本仓库合成示例，先形成 brief 和计划，再执行并给证据审查。智慧芽和邮件留作现场配置，不能声称已连接。产物保存在本地项目目录。

上游完整技能快照位于 `../../vendor/superpowers/`，固定 revision 及每份文件的 SHA-256 见 `snapshot.json`。可选浏览器 companion 需要 Node 和 shell；本适配默认采用 Markdown，避免自动启动服务或遥测。
