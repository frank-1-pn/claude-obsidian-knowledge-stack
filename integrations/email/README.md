# 私人邮件助理：连接、管理与三个 Skill

**交付状态：设计与技能模板。未连接邮箱、未启动监控、未启用每日发送或紧急推送。** 本目录将用户提供的 [完整实施方案](../../docs/email/workbuddy_email_assistant_implementation_plan.md) 第 11–16 章整理为可交接入口；原方案保留原始字节。

邮件管理在这里指读取、研判、待办和期限整理、每日摘要、提醒解释。首期源邮箱只读；回复草稿可以在当前对话中提供。真实邮箱写入和发送另需独立建设与授权。

## 使用场景

| 用户的请求 | 对应能力 | 回答必须带的依据 |
| --- | --- | --- |
| “这封 CRO 邮件说了什么，为什么需要我关注？” | `mail-triage` 提取事实、项目变化和候选优先级 | 消息 ID、正文段落、具体原文；项目关联不确定时说明 |
| “今天需要我处理什么，最迟什么时候？” | 查询待办并展开相关邮件、线程 | 待办责任、期限原文和归一化状态；不猜时区、不把已读当完成 |
| “给我今天的邮件简报，展开第二项。” | `daily-email-brief` 读取后台已有简报和事项 | 简报版本、业务日期、数据截至、覆盖范围与原邮件证据 |
| “为什么提醒我，这件事后来解决了吗？” | `urgent-email-alert` 查询已有提醒与后续线程 | 规则版本、提醒原因、处理证据；平台接受、本人确认和事项完成分别显示 |

没有连接服务时明确返回“邮件服务尚未接入”；连接失败、解析积压或未读附件时说明覆盖不足。不能将读取失败解释成“没有重要邮件”，也不能将附件名当成已审阅内容。

## 后台与 WorkBuddy 各自负责什么

```text
获授权企业邮箱（IMAP，只读）
  → ImapFlow 同步 Worker（文件夹 UIDVALIDITY + UID，持久游标/重连/回填）
  → MailParser（MIME、正文段落、地址、附件元数据）
  → PostgreSQL（状态、任务、证据、分析、待办、简报和 Outbox）
  → 分析 Worker（确定性规则 → 获准模型无工具提取 → Schema/证据校验）
  → 后台唯一调度（冻结每日简报快照、期限重评估）
  → Notification Worker（已批准本人渠道、去重、有界重试、投递记录）

受身份约束的只读业务查询 ↔ 只读 MCP ↔ WorkBuddy 私人邮件专家 + 三个 Skill
本人认证确认页面：明确反馈/确认；独立写接口，不属于只读 MCP
```

| 组件 | 职责与权限 |
| --- | --- |
| ImapFlow 同步 Worker | 只用获准邮箱凭证；读取批准文件夹；发现任务落库后再推进游标；历史回填不直接触发旧紧急提醒 |
| MailParser | 解析正文、题录和附件元数据；大邮件采用受控分段/流式处理；不加载远程图片、执行脚本或自动打开链接 |
| PostgreSQL / 持久队列 | 保存每文件夹状态、任务租约、不可变简报版本和通知状态，支持断线恢复和审计 |
| 分析 Worker | 使用企业批准的独立模型 API；不假设桌面订阅可供后台调用；结构化结果通过证据校验后才能进入通知决策 |
| 后台调度与通知 Worker | WorkBuddy 关闭仍独立工作；固定本人收件映射；`accepted` 只表示平台接受，超时未知为 `unknown` |
| WorkBuddy / 只读 MCP | 查阅和解释已有结果，按需展开原邮件；身份与账号范围由服务端校验，不接受模型任意选择账户 |
| 三个 Skill | 对话工作流和共享业务规范，不提供 IMAP、定时器、真实发送能力，不自动修改后台规则 |

**只有一个正式邮件调度入口。** 按源方案推荐由常驻后台生成每日邮件简报和提醒，不能再配置同样的 WorkBuddy 晨报任务形成双调度。后台读取共享版本化分析规范，而不是未经确认地远程运行桌面 Skill。

私人邮件专家需在运行时真正隔离：只绑定本人只读邮件 MCP 和必要回复能力，不同时获得公开搜索、智慧芽、任意文件读取或发送工具。若目标版本不能形成足够隔离，需独立运行环境或后端强制网关，不能只靠提示词。

## 三种连接分别准备

| 连接 | 谁持有凭据 | 现场需要确认 | 成功证据 |
| --- | --- | --- | --- |
| 邮箱登录 | 同步 Worker 的秘密管理系统 | 服务商、真实主机/端口/TLS、IMAP 开放、OAuth/专用授权码、账户/文件夹/历史范围、网络白名单 | 测试邮件读取正确；独立客户端确认已读标志和位置未改 |
| 本人通知通道 | 独立 Notification Worker | 源方案候选企微自建应用；核对本人映射、可见范围、权限、出口、内容披露和时段 | Outbox 与实际平台投递结果关联；区分接受、未知和本人确认 |
| WorkBuddy 只读 MCP | WorkBuddy 连接器的服务令牌/企业认证 | 批准 HTTPS 端点、传输/认证与版本兼容性、令牌绑定本人、到期和撤销 | 工具发现、认证查询、分页、越权拒绝、撤销、停机测试 |

**MCP 令牌不是邮箱密码；登录邮箱也不会自动接通通知。** 不猜主机名、不关闭 TLS 校验、不要求把密码/Token 放进聊天，厂商参数由 IT 提供正式资料。

生产优先评估批准的 HTTPS 远程 MCP；没有批准入站路线时才评估本地 stdio 代理连接受控后台 API。代理不是常驻邮件服务。WorkBuddy 配置字段、凭证变量和认证方式按客户版本联调；[连接资料示例](connector-profile.example.json) 是中立待填表，**不是可导入的 WorkBuddy 配置**。

继续复用 WorkBuddy 已有通信连接器，本包不添加微信抓取器或飞书 bridge。源方案邮件专项通知适配器是否可调用已有获准通道，现场验证后再选。普通会话回复不能默认作为总监离线时的主动提醒，群 Webhook 不能默认代替本人私信。

## 七个拟实现的只读 MCP 工具

以下是原方案定义的项目工具，**不是 WorkBuddy 自带，也未在本轮提供服务实现**。

| 工具 | 输入要点 | 输出及用途 |
| --- | --- | --- |
| `mail_get_sync_status` | 无账号切换参数 | 授权范围、最后检查时间、积压、失败与新鲜度；回答前识别数据缺口 |
| `mail_search_messages` | `query`、from/to 时间范围、`project_id`、`cursor`、`limit` | 本人范围内摘要和引用；定位相关邮件后按需展开 |
| `mail_get_message` | `message_id`、`paragraph_cursor`、`limit` | 分页正文、题录、覆盖和证据段落；核查事实/期限 |
| `mail_get_thread` | `thread_id`、`cursor`、`limit` | 按时间排列往来及关联可靠性；分清历史引用与新证据 |
| `mail_get_daily_brief` | `local_date` | 已生成简报版本和覆盖状态；不存在时明确返回 |
| `mail_get_pending_items` | `project_id`、`status`、`cursor`、`limit` | 待办和来源，不等同本人全部线下事项 |
| `mail_get_alert` | `notification_id` | 提醒理由、规则版本、证据、平台接受与本人确认状态 |

工具不开放邮箱写入、任意 SQL/URL/文件/shell。身份来自验证通过的认证，服务器附加 owner/account 范围；跨账号 ID 不泄露内容或存在性。只读注解不是权限控制。

## 连接与启用顺序 M0–M6

按 [逐项接入与验收清单](setup-checklist.md) 操作：

1. **M0 接入确认**：取得 IT 参数、批准数据/模型/通知范围，本人确认项目、联系人、提醒条件、时间、免打扰与保留策略。
2. **M1 只读同步**：模拟邮箱先行；UID/UIDVALIDITY、任务租约、回填/恢复，独立客户端证明源邮箱未改。
3. **M2 邮件分析**：事实、线程、期限、证据校验和 P0/P1/P2，分开的校准/验收集确定误报漏报门槛。
4. **M3 简报与提醒**：唯一后台调度、冻结快照、Outbox、本人通知和认证确认页，验证重启/未知投递/重复触发。
5. **M4 WorkBuddy 接入**：真实版本联调只读 MCP 与三 Skill，验证身份、分页、权限和工具隔离。
6. **M5 影子运行**：获准真实数据分析，对照人工判断，默认不自动推送业务提醒。
7. **M6 正式启用**：本人和 IT 验收后分级放开推送，固定版本，演练回退/故障/轮换/撤销。

示例频率和目标不是服务承诺。夜间 P0、升级其他人和完整项目内容披露由本人/企业单独确认。

## 与公开每日资讯的边界

[每日资讯](../daily-briefing/README.md) 收集用户关注主题的公共信息，支持 AI 总结和来源链接。每日**邮件**简报基于本人授权邮件，包含待办和私人项目证据。两者不共享邮件正文、凭据、缓存、任务或通知策略，不把内部邮件自动作为公开资讯素材，不为补全私人邮件调用公开搜索。
