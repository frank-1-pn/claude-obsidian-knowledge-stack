# 私人邮件助理：现场实施扩展

本轮状态：设计与模板，**未连接邮箱、未启动监控、未启用每日发送或紧急推送**。详细来源是用户提供的 [workbuddy_email_assistant_implementation_plan.md](../../docs/email/workbuddy_email_assistant_implementation_plan.md)，原文件原样归档到分享文档。

## 预期结构

`ImapFlow（获准 IMAP 只读） → MailParser → 持久后台/队列 → 事实与证据校验 → 每日简报 / 紧急提醒`。WorkBuddy 通过只读 MCP 查询、追问和解释已有结果。常驻后台负责调度、去重、重试和覆盖状态，关闭桌面对话不应让正式监控失效。具体邮箱、认证方式、企业批准模型、网络、保留策略和通知渠道须现场核对。

对外通讯继续复用已有 WorkBuddy 连接器；本包不搭通用 bridge。原方案中的通知适配器是邮件专项候选，是否能调用已有批准连接器、是否需要独立通知服务，留待现场确认。不能把普通会话回复默认当成总监离线时也能收到的主动提醒。

## 三个预设技能模板

- `mail-triage`：提取事实、事项、截止时间，解释候选优先级。
- `daily-email-brief`：查询/展开已经生成的本人每日简报。
- `urgent-email-alert`：解释已有提醒的依据、后续变化及当前状态。

模板不提供 IMAP、定时器或发送能力。后台与对话共享版本化业务规则，不随一次口头反馈自动改正式政策。总监可以现场确认重要项目/联系人、必须提醒事件、时区、免打扰和误报/漏报容忍；“urgent”关键词本身不足以判立即提醒。

## 保留的只读与证据边界

源邮箱不提供发信、删除、移动、标记已读或改规则工具；只读 MCP 不开放任意 SQL/URL/文件/shell。身份和账号范围由服务端控制。私人邮件专家的运行工具要真正隔离，不能只靠提示词阻止向公开搜索、智慧芽或团队笔记外发内容。

每条判断保留消息与段落证据、期限原文、附件/线程/已发送文件夹覆盖和最后同步时间。同步失败不等于没有重要邮件；已读不等于处理；平台接受不等于本人看到或事项关闭。附件首期只读元数据，未分析不能声称已审阅。

## 现场验收入口

按原方案 M0–M6：连接/数据权限确认 → 只读同步 → 分析及证据验证 → 后台简报/通知 → WorkBuddy MCP → 影子对照 → 有条件正式启用。必须覆盖断线补拉、UIDVALIDITY变化、重复/迟到邮件、凭据撤销、越权ID、正文指令注入、未知投递状态、后台停机和来源邮箱不变等用例。本轮只交付这些设计与不启用连接的模板。
